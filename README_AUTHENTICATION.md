# 🔐 Authentication Implementation

## Overview

This application now uses **JWT-based authentication** powered by **Supabase Auth**. All API endpoints (except authentication endpoints) require a valid access token.

## 🚀 Quick Start

### 1. Environment Setup

Ensure your `.env` file has Supabase credentials:

```bash
# Development Database
SUPABASE_URL_DEV=https://your-project.supabase.co
SUPABASE_KEY_DEV=your-anon-key
SUPABASE_SERVICE_ROLE_KEY_DEV=your-service-role-key

# Environment
ENVIRONMENT=development
```

### 2. Start the Backend

```bash
cd backend
python main.py
```

The server will start at `http://localhost:8000`

### 3. Register Your First User

```bash
curl -X POST http://localhost:8000/api/v1/auth/register \
  -H "Content-Type: application/json" \
  -d '{
    "email": "your@email.com",
    "password": "yourpassword",
    "name": "Your Name"
  }'
```

### 4. Use Your Access Token

Copy the `access_token` from the response and use it in subsequent requests:

```bash
curl -X GET http://localhost:8000/api/v1/entries/ \
  -H "Authorization: Bearer YOUR_ACCESS_TOKEN"
```

## 🎯 Key Features

### Security

- ✅ JWT token validation
- ✅ Automatic token expiry (1 hour)
- ✅ Refresh token mechanism (7 days)
- ✅ Secure password hashing via Supabase
- ✅ User data isolation

### User Isolation

- ✅ Each user can only access their own data
- ✅ Database queries filtered by user_id
- ✅ Ownership validation on updates/deletes
- ✅ No cross-user data access

### Error Handling

- ✅ 401 for invalid/expired tokens
- ✅ 404 for entries that don't exist or don't belong to user
- ✅ 409 for duplicate email registration
- ✅ Descriptive error messages

## 🔄 Token Lifecycle

```
1. User logs in → Receives access_token + refresh_token
2. Use access_token for API requests (valid for 1 hour)
3. Token expires → Get 401 Unauthorized
4. Use refresh_token to get new access_token
5. Continue using new access_token
6. Refresh token expires after 7 days → User must login again
```

## 📊 Database

### System User

- All existing data (930 entries) belongs to system user
- System User ID: `00000000-0000-0000-0000-000000000001`
- Email: `system@example.com`

### New Users

- Start with empty entry list
- Each user's data is completely isolated
- User IDs are UUIDs generated by Supabase

### Database Schema

```sql
-- Entry table has user_id column
ALTER TABLE entry ADD COLUMN user_id UUID NOT NULL;

-- Foreign key constraint ensures user exists
ALTER TABLE entry ADD CONSTRAINT entry_user_id_fkey
  FOREIGN KEY (user_id) REFERENCES auth.users(id);
```

## ⚠️ Common Issues

### 401 Unauthorized

**Problem:** API returns 401 error

**Solutions:**

- Ensure you're sending the `Authorization` header
- Check token hasn't expired (refresh if needed)
- Verify token format is `Bearer <token>` (with space)

### 404 Entry Not Found

**Problem:** Entry exists but returns 404

**Solutions:**

- Entry might belong to another user
- Verify you're logged in as the correct user
- Check entry ID is correct

### 409 Conflict on Registration

**Problem:** Can't register new user

**Solutions:**

- Email already registered
- Use login endpoint instead
- Try different email address

### Code Example

**Protecting a route:**

```python
from middleware.auth import get_current_user_id
from uuid import UUID

@router.post("/entries/")
async def create_entry(
    entry: EntryCreate,
    user_id: UUID = Depends(get_current_user_id)
):
    # user_id is automatically extracted from JWT
    return await EntryService.create_entry(..., user_id=user_id)
```

**User-scoped query:**

```python
async def get_entries(user_id: UUID):
    query = db.client.table("entry").select("*")
    query = query.eq("user_id", str(user_id))  # Filter by user
    result = query.execute()
    return result.data
```
